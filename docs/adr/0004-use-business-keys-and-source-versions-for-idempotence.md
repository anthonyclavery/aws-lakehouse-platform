# ADR 0004: Use business keys and source versions for idempotence

## Status

Accepted.

## Context

The V1 data is generated by this project. It requires idempotent replays and correction handling, but it does not consume an external CDC platform with independent message identifiers.

## Decision

Each flow uses a stable business key and `source_version`. An unchanged replay is ignored. A record with the same business key and a greater version is a correction. Batch manifests and the ingestion audit record file-level processing. The V1 contracts do not include `source_event_id`.

## Consequences

The contracts remain focused on business meaning while still supporting deduplication and correction. A future integration with an external CDC producer may add a source-message identifier as technical metadata.
